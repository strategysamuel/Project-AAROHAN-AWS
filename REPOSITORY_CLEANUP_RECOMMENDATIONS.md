# Repository Cleanup Recommendations

Do not delete anything automatically. Review the items below before publishing the repository publicly.

## Generated Build Artifacts

| Item | Current Examples | Recommendation | Why |
| --- | --- | --- | --- |
| Frontend build output | `dist/`, `apps/customer-portal/dist/` | Remove from the publication branch if they are only local build outputs | These folders are generated by the build and should not be treated as source of truth |
| Turbo cache | `.turbo/`, `apps/customer-portal/.turbo/` | Exclude from publication and clear before release packaging | Cache files are local and machine-specific |
| Test cache | `.pytest_cache/` | Remove before publishing | Pytest cache can go stale and is not source code |

## Local Databases

| Item | Current Examples | Recommendation | Why |
| --- | --- | --- | --- |
| Demo SQLite databases | `aarohan_local.db`, `services/auth-service/aarohan_local.db`, `services/ocen-uli-service/aarohan_local.db` | Keep only if intentionally checked in for demo reproducibility; otherwise move to generated-artifact handling | These are runtime data stores and may contain environment-specific state |
| Demo datasets | `ese/datasets/msme/banking.db`, `ese/datasets/test_temp_generator/banking.db` | Review and keep only the canonical seeded dataset | Temporary generator databases should not ship as accidental artifacts |

## Developer Environment Artifacts

| Item | Current Examples | Recommendation | Why |
| --- | --- | --- | --- |
| Node dependencies | `node_modules/` | Exclude from publication | Reinstallable dependency cache |
| Python bytecode | `__pycache__/`, `*.pyc` | Remove if present | Generated by Python runtime |
| Logs | `*.log` files under any workspace folder | Remove or ignore | Logs are useful locally but not for public repo delivery |

## Content Hygiene Checks

- Confirm only the intended markdown submission documents are committed alongside the source code.
- Ensure no temporary report exports, preview bundles, or one-off diagnostic files are left in the root.
- Verify that any local demo database that remains in the repository is intentional and documented.
- Make sure the README and judge-facing docs point to existing files only.

## Recommended Pre-Publication Review

1. Review every file under `.turbo/`, `.pytest_cache/`, and `dist/`.
2. Check for leftover local database files in the root and service folders.
3. Reconfirm that generated demo artifacts are not mixed with hand-authored documentation.
4. Keep the repository focused on source, canonical documentation, and deliberate demo assets.
